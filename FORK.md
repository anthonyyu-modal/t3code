# anthonyyu-modal/t3code

Upstream T3 Code plus a small patch stack, released from this repository.

## What differs from upstream

- **Linux `t3` runs on Oracle UEK kernels.** UEK refuses an ELF whose last `PT_NOTE` is over 4 MiB, and Node's single-executable blob is ~13 MB. `scripts/build-cli-archive.ts` gives the blob its own `PT_NOTE`.
- **Remote install errors say why.** The SSH runner reports `t3 --version` output and `uname` when a downloaded binary does not run.
- **SSH tunnels ignore failing `LocalForward`s** from `~/.ssh/config` (no `ExitOnForwardFailure`).
- **Archives come from this fork.** `CLI_RELEASE_REPOSITORY` in `packages/shared/src/cliRelease.ts` points here, so SSH remotes and runtimes install this fork's patched archives.
- **Unsigned macOS builds are ad hoc signed and self-update in-app from the release `.zip`** (`scripts/build-desktop-artifact.ts`, `apps/desktop/src/electron/MacZipUpdater.ts`): macOS refuses notifications from an app whose bundle is not signed, and Squirrel.Mac cannot install an ad hoc signed update because its designated requirement pins the running binary's `cdhash`. Unsigned macOS builds publish `nightly-mac.yml` and replace `/Applications/T3 Code (Nightly).app` directly from the verified `.zip` archive via `ditto --noqtn` without setting `com.apple.quarantine`.
- **Settings → General → Test notification** posts a notification on demand: macOS lists an app in System Settings → Notifications only after it posts one.
- **In-app alerts can also send a system notification** (Settings → General → System notifications for in-app alerts, off by default, kept on this device), so an alert stays clickable in Notification Center after its in-app toast disappears.
- **Settings rows this fork adds carry a Fork badge** (`forkSetting` in `apps/web/src/components/settings/forkSetting.tsx`); searching settings for "fork" lists them.
- **A divider line separates pinned threads** from unpinned ones in the sidebar.
- **Threads with an open pull request stay at full strength in the sidebar.** Upstream dims a thread once you have read its finished run, or while it works in the background. Here an open PR keeps it bright until the PR merges or closes (`shouldRecedeSidebarThread` in `apps/web/src/components/Sidebar.logic.ts`). Settled and snoozed rows stay grey.
- **Short threads get their own Quick section** (Settings → General → Quick section, on at 2 messages by default, kept on this device). An Active thread where you have written at most that many messages sits in a collapsible Quick shelf below Active, latest activity first, and moves up to Active once you write more. Quick threads can be dragged to Pinned or Settled, but nothing drops into Quick. The server sends the count as `userAuthoredMessageCount` on each thread shell, so threads from a server without this fork's build stay in Active.
- **Forked threads and `/btw` / `/side` side chats nest underneath their parent thread in the sidebar** as compact tree sub-rows (`apps/web/src/components/sidebar/SidebarThreadRow.tsx` and `apps/web/src/components/Sidebar.logic.ts`), capped at two indent levels, with a count pill on the parent to collapse or expand its branches and a status dot while collapsed if a hidden child needs attention. Full forks show a `⑂` icon, keep inbox fork families out of Quick once any live branch exceeds the Quick limit, and stay in Active with a clickable `⑂ parent` breadcrumb chip when their parent moves to another shelf. Side chats (`lineage.sideChat`) show a chat icon, open in their parent thread's right-panel side-chat tab on click, highlight while that tab is open, and tuck away when settled or when their parent leaves the inbox.
- **Side chat is a composer toggle** (`apps/web/src/components/chat/ComposerSideChatToggle.tsx`, `sideChatArms.ts`). On main threads whose server and provider support side chats (native fork or portable handoff — all built-in providers), a **Side chat** toggle sits next to the attach button in the composer footer, and picking `/side` or `/btw` from the slash menu anywhere in a prompt toggles it on or off instead of prefixing the text with `/side `. While toggled on, the composer highlights in blue with `"Ask a side question…"` placeholder and `"Send in side chat"` submit label, sends even while the main thread is running without steering or queueing it, disarms on send (restoring if the start fails), and clears on `Escape` when empty. Typing `/side …` or `/btw …` directly still works and also lights up the toggle (clicking it off strips the prefix).
- **Thread thumbnails** (Settings → General → Thread thumbnails): a self-hosted image model draws a picture for each thread from its title, shown on its sidebar card. The client calls the endpoint directly with an OpenAI-style images request and caches 96px WebP thumbnails in IndexedDB, all per device (`apps/web/src/threadThumbnails.ts`). The matching Modal app lives outside this repository in `~/workspace/projects/t3-thumbnails`.
- **Titles can follow the conversation** (Settings → Threads → Regenerate titles after each turn, off by default, per environment with project overrides). When a run completes, the server asks for the same title regeneration as the thread menu's Regenerate title, keyed by run so a run regenerates once (`apps/server/src/orchestration-v2/ThreadTitleAutoRegenerationReactor.ts`). It also replaces titles you set by hand. Mobile has no control for it yet.
- **Thread details surfaces Hot links extracted from your messages** (`apps/web/src/components/chat/ThreadHotLinksPanel.tsx` and `apps/server/src/orchestration-v2/ThreadHotLinksService.ts`, toggleable in the Thread details context menu as **Hot links**). Using the configured title-generation model solely on user-authored messages (including inherited pre-fork user messages, never assistant replies or tool output), the server selects and labels up to six central external links such as Plain support threads, Slack threads, Linear issues, Notion pages, Datadog views, or GitHub links, validates every returned URL against URLs present in those user messages, and caches results in SQLite (`fork_thread_hot_links`) by message fingerprint.
- **Selecting a word in the file viewer highlights its other occurrences**, like VS Code's selection highlight. Matching is by text: case-sensitive and whole-word, with `_`, `$`, digits, and letters in any script counted as word characters. It has no language server, so it cannot tell two variables with the same name apart. Painted with the CSS Custom Highlight API (`apps/web/src/components/files/wordOccurrenceHighlights.ts`).
- **The Changes panel highlights a diff with the whole file in view.** A patch holds only the lines around each change, and upstream highlights every hunk as if the file began there, so a hunk that starts inside a docstring or block comment takes the closing delimiter for an opening one and colours the code after it as a string. Here the panel loads the files of the diffs on screen, two at a time and newest first, with the same request that expanding unchanged lines makes (`apps/web/src/components/diffs/usePartialDiffHydration.ts`). That covers working tree, branch, and commit diffs. Turn diffs, tool call diffs, and the pull request Code tab still highlight hunk by hunk: the first two have no request that returns a file's contents, and the pull request tab would spend four GitHub API calls on every file scrolled into view.
- **The file view copies paths from its breadcrumb.** The copy button after the breadcrumb copies the open file's or folder's full path, and right-clicking any breadcrumb segment offers **Copy full path** and, inside the workspace, **Copy relative path** for that segment (`apps/web/src/components/files/FilePathCopy.tsx`). Upstream copies a path only from the file tab's context menu, and only relative to the workspace.
- **Citing an assistant selection has a shortcut** (Settings → Keybindings → Composer: Cite Selection, `mod+shift+.` by default). With text selected in an assistant response, the shortcut inserts its quote chip into the composer and opens the inline comment box, just like the floating **Cite** button (`assistantSelection` is also available as a `when` condition for single-key bindings).
- **Whiteboards that you and agents both draw on, open to every thread on the server** (right panel → **+** → Whiteboard, or the command palette; [user guide](docs/user/whiteboard.md)). Each is an Excalidraw board kept as a JSON file under T3 home (`userdata/whiteboards/shared/`, beside an `index.json` that lists the boards and records which one each thread's tab shows) rather than in SQLite, so this fork owns no migration id that upstream could later reuse. A thread's tab starts without a board and offers a new one, named after the thread, or any board there is. Boards from when each thread kept its own (files directly in `userdata/whiteboards/`) join the list, under their threads' titles, the first time the server reads its boards. Agents read a board with `whiteboard_read`, draw with `whiteboard_edit` (including colours, separate label `textColor`, text/vertical alignment, shipped fonts `Excalifont`/`Nunito`/`Lilita One`/`Comic Shanns`/`Cascadia`, `strokeWidth`, `startArrowhead`/`endArrowhead`, `opacity`, `group`, `fillStyle`, `roughness`, and `roundness`), and get a picture with `whiteboard_view` (`apps/server/src/whiteboard/`, `apps/server/src/mcp/toolkits/whiteboard/`). A window that shows the board draws the picture. When none does, the server draws it (`WhiteboardPictures.ts`): it opens a page of the web client (`apps/web/src/whiteboardPicture.ts`, which runs the same Excalidraw export as the window) in the headless browser upstream installs for agents' browser tools, answers that page from the client's files on disk, and refuses every other request, so nothing on a board is fetched. The tools act on the board the thread's tab shows unless the agent names another, drawing in a thread without a board starts one, an agent's drawing opens the tab on the board it drew on, and what changed on the board a thread shows reaches Claude and Codex agents as a note with the next message, through the MCP app context upstream delivers to both. The tools act as the calling thread, so outside MCP clients are not offered them. While the keyboard is in the board, Excalidraw's shortcuts win over T3 bindings on the same chords (`apps/web/src/lib/whiteboardKeys.ts`, consulted by `resolveShortcutCommand` and the command dispatcher), and a sideways trackpad swipe pans the board instead of going back. The five boards shown most recently stay mounted apart from the panel (`apps/web/src/components/whiteboard/liveBoards.tsx`), because Excalidraw keeps its undo history only in the mounted component and the panel rebuilds a tab each time it is shown. Excalidraw's fonts ship with the app (`apps/web/vite/excalidrawFonts.ts`) because the desktop content policy blocks its CDN, and `pnpm-workspace.yaml` overrides its Radix Tabs pin so React 19 passes the strict peer check. Mobile has no tab for it yet.
- **Cursor reads `<cwd>/AGENTS.md` with cwd-bounded `@path` imports** (`packages/provider-cursor/src/server/projectInstructions.ts`, wired in `adapter.ts`). Upstream strips `"project"` from `@cursor/sdk`'s `settingSources` outside unrestricted `full-access` so untrusted repos cannot run hooks or `.cursor/mcp.json`, which also skips `AGENTS.md`, and `@cursor/sdk` does not expand `@path` references even in `full-access`. Here T3 reads `<cwd>/AGENTS.md` once on turn 1 (and after compaction or rollback), recursively expands `@path` references up to depth 5 / 64 KB only when their `realpath` stays inside `<cwd>` (ignoring code blocks, inline code, symlinks escaping `<cwd>`, and binary files), and in `full-access` injects only the expanded imports so `AGENTS.md` itself is not duplicated.
- **Markdown file links with custom text render inline on that text instead of appending a file chip** (`apps/web/src/components/ChatMarkdown.tsx`, `apps/web/src/components/chat/MarkdownFileLink.tsx`, `packages/shared/src/threadFindText.ts`, `packages/provider-core/src/server/runtimeInstructions.ts`). Links whose label names the target file (such as `[http.ts:42](/abs/path/http.ts:42)`) and bare inline code paths stay standard file chips, while links with prose or symbol labels (such as ``[`BaseAgentLoop`](/abs/path/loop.py:697)`` or `[660 s deadline](/abs/path/loop.py:623)`) make the label itself clickable with the same file viewer open, Cmd/Ctrl-click editor open, context menu, drag, copy, and hover tooltip (with file icon, path, and line range) behavior. Runtime instructions tell agents they can attach code links directly to symbols or phrases to reduce clutter when citing many locations inline. Mobile has no custom-labeled rendering for this yet.
- **T3 MCP tools accept JSON-string fallbacks for depth-3 nested fields that Cursor's `CallDynamicTool` corrupts on Gemini** (`packages/contracts/src/orchestratorMcp.ts`, `packages/contracts/src/model.ts`, `apps/server/src/mcp/toolkits/whiteboard/tools.ts`, and Cursor-only guidance in `packages/provider-cursor/src/server/adapter.ts`). Cursor wraps MCP tools behind an untyped `CallDynamicTool` whose Gemini serializer mangles depth-3 objects and nested arrays (such as `delegate_task` `target.options` arriving as `[true]` or `whiteboard_edit` `points` breaking). T3 decodes JSON-stringified `options` (`delegate_task`, `t3_thread_launch`, `t3_thread_configure`), `create_threads` `target`, and `whiteboard_edit` `points` at the schema boundary while `advertisedJsonSchema` strips the string branches so Claude/Codex schemas stay unchanged, and Cursor MCP sessions are told to pass those fields as JSON strings.
- **`fork-release.yml`** builds the macOS arm64 app and the macOS arm64 + Linux x64 CLI archives on GitHub-hosted runners and publishes a release on the nightly train. Every other workflow is disabled in this repository.

## Release

```bash
gh workflow run fork-release.yml -R anthonyyu-modal/t3code
```

Builds are nightly versions (`T3 Code (Nightly)`, Orchestrator V2, nightly-only settings) and ad hoc signed. Once installed in `/Applications`, the desktop app checks this repository's releases and installs newer builds in-app from the `.zip` archive without quarantine prompts.

## Install (macOS, first time)

```bash
gh release download -R anthonyyu-modal/t3code -p '*arm64.dmg' -D /tmp/t3-fork --clobber
```

Open the .dmg and drag the app to Applications. It installs as `T3 Code (Nightly).app`, replacing the official Nightly, and uses the same `~/.t3` data. If you downloaded the `.dmg` in a browser and macOS refuses to open it (unverified developer, or "damaged"): `xattr -dr com.apple.quarantine "/Applications/T3 Code (Nightly).app"`. Subsequent updates install in-app.

## Sync with upstream

`main` is always the commit the newest upstream nightly was built from, with this fork's commits as one linear stack on top:

- **Base on the newest nightly, not upstream `main`.** Nightlies are what upstream has released; `main` can be ahead of them.
- **Rebase, never merge.** Fork commits must never sit between upstream commits. New fork commits go on top of the stack.
- **Drop patches upstream made unnecessary.** On every sync, check each fork commit against what upstream shipped. If upstream fixed the same problem, delete the commit from the stack (skip it in the rebase) instead of keeping or reverting it.
- **Check the stack before pushing.** Upstream's types and lint rules change under the fork's code, and the release workflow runs neither. Use the Node version in `package.json` `engines`, and fold each fix into the fork commit that owns the code (`git commit --fixup`, then `git rebase -i --autosquash "$nightly"`).
- **This fork's own copy stays English.** Upstream translates its UI and fails lint on untranslated copy (`t3code/no-untranslated-copy`). Files the fork adds start with a file-wide `oxlint-disable` for that rule, and fork lines inside upstream files carry an `oxlint-disable-next-line`, both giving that reason, so the fork adds nothing to upstream's translation catalogs.

```bash
git fetch upstream --tags
nightly=$(gh release list -R pingdotgg/t3code --limit 20 --json tagName \
  -q '[.[] | select(.tagName | test("-nightly\\."))][0].tagName')
git rebase --onto "$nightly" "$(git merge-base main upstream/main)" main
pnpm install && pnpm typecheck
git diff --name-only "$nightly" -- '*.ts' '*.tsx' | xargs pnpm exec vp lint
git push --force-with-lease origin main
gh workflow run fork-release.yml -R anthonyyu-modal/t3code
```

If upstream added workflows, disable them here (`gh workflow disable <name> -R anthonyyu-modal/t3code`); only Fork Release and Release desktop build stay enabled.
